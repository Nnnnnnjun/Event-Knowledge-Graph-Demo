# 数据说明

本目录包含两类数据：

- `xuanwumen_text.txt`：项目自建的教学用文本，**已随仓库提供**；
- `event-covid-19-v0.2.json`：OpenKG 新冠事件数据，**不随仓库分发**，需要自行下载。

---

## 1. `xuanwumen_text.txt`

这是一段约 600 字的玄武门之变历史摘要，用于演示“从零构建事件图谱”的完整流程。

需要明确：

- 它是**现代汉语教学摘要**，不是《旧唐书》《资治通鉴》的逐字原文；
- 它经过压缩和改写，事件数量、人物对话、时间细节都不适合作为史学研究依据；
- 它只用于测试抽取、对齐、审核、建图这条工程链路。

如果你要换成自己的文本，保持 UTF-8 编码，并覆盖同名文件即可。Notebook 会自动读取。

---

## 2. `event-covid-19-v0.2.json`（需自行下载）

### 来源

该文件来自 OpenKG 新冠事件数据，项目实践时使用了
[xyjigsaw/COVID19-KBQA-DEMO](https://github.com/xyjigsaw/COVID19-KBQA-DEMO) 转存的版本。

建议的获取方式：

1. 打开 [https://github.com/xyjigsaw/COVID19-KBQA-DEMO](https://github.com/xyjigsaw/COVID19-KBQA-DEMO)；
2. 在仓库中找到 `event-covid-19-v0.2.json`；
3. 下载后放到本目录：`data/event-covid-19-v0.2.json`。

也可以从 OpenKG 的数据页面寻找同名资源。不同镜像/版本可能字段一致但记录数略有差异，
以你实际下载到的文件为准。

> 本仓库**不重新分发**该 JSON 文件：它体积较大，且版权/许可归原始数据方所有。
> `.gitignore` 已排除 `data/*.json`，避免误提交。

### 字段映射

| 字段 | 含义 | 本项目的用法 |
|---|---|---|
| `@id` | 事件 URI | `COVIDEvent.id` 主键 |
| `@type` | 事件类型（C2 新闻 / C3 政策） | 仅作参考，实际用 `P1`/`P6` 判断 |
| `P0` | 新闻发生时间 | 新闻事件时间 |
| `P1` | 新闻标题 | 新闻事件标题 |
| `P2` | 新闻摘要 | 节点属性 |
| `P3` | 新闻链接 | 未入库（保留在原始数据） |
| `P4` | 新闻来源 | 节点属性 |
| `P5` | 之前发生的事件 | 指向链上前一个事件 |
| `P6` | 政策标题 | 政策事件标题 |
| `P7` | 政策发布日期 | 政策事件时间 |
| `P9` | 政策发布机构 | 节点属性 |
| `P12` / `P15` | 政策摘要 / 正文 | 节点属性（截断到 1000 字符） |
| `P16` | 后续政策 | 指向链上的下一个政策 |

### 一个容易误读的细节

`P16` 的中文标签是“后续政策”，但原始 Notebook 把它和 `P5` 一样当成“前序指针”，
统一写成 `target -> current`。这会导致 **139 条 `P16` 全部反向**：

- 20 条 `P16` 跨天，表现为时间倒置；
- 119 条 `P16` 是同一天，方向错了但时间戳看不出来；
- 再加上 1 条 `P5` 同天逆序、1 条 `P16` 跨类，最终有 22 条边在时间上倒置。

本项目的 Notebook 按字段语义定向：

- `P5`：`target -> current`；
- `P16`：`current -> target`；
- 用 `time_valid` 做二次校验；
- 默认保留全部 194 条指针（2 条时间倒置）；
- 设置 `STRICT_TIME_ORDER=true` 时，只写入 192 条通过校验的边。

### 数据规模（按本仓库脚本实测）

| 指标 | 数值 |
|---|---|
| 事件总数 | 195 |
| 新闻事件（`P1`） | 55 |
| 政策事件（`P6`） | 140 |
| 带 `P5`/`P16` 指针 | 194 |
| 指针可解析 | 194 |
| 按语义定向后时间倒置 | 2 |
| 缺时间 | 0 |
| 严格模式边数 | 192 |
| 连通分量 | 1 |

> 原组会 PPT 将事件数记为 194；本仓库按 JSON 实际解析为 195。
> 差异来自统计口径（是否把某条边界记录算入），代码以实际解析结果为准，不强行对齐 PPT 数字。
